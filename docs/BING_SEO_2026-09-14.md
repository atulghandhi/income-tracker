# Bing search improvements — 14 September 2026

## Objective and evidence

Increase relevant Bing web-search clicks and conversions into tracker use. No Bing query/impression/click baseline was available during implementation; the accessible Bing browser session was signed out. The opportunities below are hypotheses based on the app's functions and current content, not measured search volumes or ranking promises.

The live site already returned 200 for the homepage, robots.txt and sitemap.xml and a real 404 for an unknown URL. It already had 20 bank guides, 10 calculators and other static content. Those strengths were preserved.

## Changes

- The complete existing React landing page is rendered into production HTML at build time: visible copy, bank links, resources and FAQs are available without JavaScript. Client interactions still use the same component. The duplicate long noscript homepage is replaced with a short explanatory note in the production build.
- Homepage title leads with “Free Income & Expense Tracker UK”; its description states the task, CSV import and no-sign-up benefit. The monthly surplus tool now also describes its purpose as an income and expenditure calculator, while preserving its URL.
- Three distinct tools have formulas and worked examples in static HTML, live inputs, query-link support, validation, FAQs, canonical URLs and structured data:
  - `/tools/weekly-to-monthly-budget-calculator.html`: weekly, fortnightly, four-weekly, monthly and yearly conversion. Explicitly separates average budgeting amounts from actual paydays.
  - `/tools/split-bills-by-income-calculator.html`: proportional versus equal contributions with penny-preserving totals, income left and insufficient-income states.
  - `/tools/christmas-budget-savings-calculator.html`: itemised festive costs, existing savings and actual paydays before a chosen shopping deadline. Evergreen URL; no artificial yearly duplicate.
- New pages are linked from the homepage, calculator hub and relevant established guides, and included in sitemap/feed indexes. No doorway pages or invented reviews/ratings.
- Modification dates are page-specific and stable across builds. Legacy dates remain unchanged until the page is revised. Bing ignores changefreq/priority, so they are omitted from sitemap output.
- Section `index.html` aliases permanently redirect to their canonical directory URLs. The offline utility receives an explicit noindex response header. Existing 404 handling is preserved.
- IndexNow requires an explicit date range or URL list, defaults to preview, and checks the live verification key, deployed sitemap dates, 200 responses and canonical/indexable HTML before posting. HTTP 200/202 means accepted for processing, not indexed.
- Production build audits every sitemap page for canonical URLs, unique titles, descriptions, one h1, local links, JSON-LD syntax and valid dates. Browser tests cover the new tools, mobile width, no-JavaScript content and existing SEO/app entry flows.

## Measure the result

In Bing Webmaster Tools, select the canonical property `https://www.theincometracker.com/` and the web-search report. Export the 28 days before deployment as the baseline. Compare with the next complete 28 days, separating new pages from established pages. Christmas intent is seasonal, so a pre/post increase is not by itself proof of an SEO effect.

Track clicks first, with impressions, CTR and average position explaining the change. Break results down by page, query, country and device where the report allows. Keep AI citations separate from web clicks. Also inspect conversion events (`cta_click`, `calc_used`, `landing_ref`) and Vercel's referrer breakdown; calculator input values must not be used as event properties.

Prioritise existing pages with meaningful impressions and weak CTR at positions where clicks are plausible. Rewrite titles/descriptions around the actual query intent, keeping page content consistent. Inspect excluded new URLs before writing more pages. If demand appears for related queries, improve the relevant page before making another one.

After publishing, verify the live sitemap in Bing and inspect the three new tools and homepage. Re-submit only pages that have actually changed. Use `npm run indexnow -- --since 2026-09-14` to preview this batch, then add `--submit`.
